# DS Bot Next 0.2.7

0.2.7 是本站点 `main` 上的第一个版本。有两样东西共用这个版本号，但不是同一个构建：

- 可安装包 `ds-bot-next-0.2.7.tgz` 由维护线（`e8e76d0`）构建，只包含下面这项交付列表排序改动。
- `main`（本仓库默认分支）还把该维护线与较新的上游引擎整合在一起。它只是源码：目前没有从它发布过 `0.2.7` 安装包。

## 交付列表排序

- 同一 `time` 的交付项现在有稳定顺序：以 id（首段是 Session id）作次级键，两个 Session 无论先读哪个，结果列表都相同。
- 跨 Session 超过 200 条时，被丢弃的条目不再随读取顺序变化。
- 新增 3 项回归测试：两种读取顺序、两个 Session 复用同一序号、200 条截断。
- 文件：`ds-bot/src/host/deliverables.js`、`ds-bot/test/deliverables.test.js`。

## main 整合额外带入的内容

- 交付列表现在包含群自己的 Session 及其更早的分段——群本身交付文件的位置。此前只扫描 `room.sessions` / `room.segments` 下的成员 Session。
- 群内接力行为遵循 main 的协议（来自上游 0.2.5）：没有按群设置的接力上限，也没有「继续」按钮。Bot 在调用工具或产出新内容时可以不受次数限制地接力；连续 6 轮只有客套确认、没有调用工具后，下一次叫人在群里留下提示并暂停，等你发言后继续。旧状态里的 `relayLimit` 与 `relays` 字段由现有迁移删除。
- 维护线的工作组、需要你处理、成果列表、fork 身份与选择性上游修复仍在，见 README。

## 已知问题（本次未修复）

在 DSH 0.2.2-rc.1 上，把群切到新的对话分段可能失败：`dsh-schedule.list` 返回分页对象，而 `ds-bot/src/host/schedules.js:132` 按数组遍历，抛出 `TypeError: records is not iterable`，群继续使用旧排期。除诊断记录外该失败是静默的；排队任务是否保留、是否仍会触发尚未验证。DSH 0.2.1-rc.4 上不出现。
